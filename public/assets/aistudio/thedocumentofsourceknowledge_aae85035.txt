An instant family-tree solver that can reconstruct, correlate, and verify a person's ancestry across historical generations could be an extremely valuable technology.

I would evaluate it as more than a genealogy application. Its potential category is an AI-powered global ancestry intelligence platform.

The real differentiator would be the ability to take a single person's known information and automatically:

Reconstruct their family tree across generations.

Correlate records from different countries, languages, and historical periods.

Identify and resolve conflicting genealogical records.

Verify parent-child relationships using documented evidence.

Connect family lines to historical populations, migration patterns, and historical figures where evidence supports the connection.

Assign confidence scores and trace every conclusion to its underlying source.

One important distinction: no system can guarantee exact ancestry throughout all history. Records are incomplete, identities can be ambiguous, and some historical relationships cannot be independently verified. A credible product would distinguish verified relationships from probable and unresolved ones.

5. Computational performance
Your 0.1 ms target is an interesting engineering benchmark.

Operation

Target

Local hash lookup

Sub-millisecond where hardware and caching permit

Cached index lookup

Sub-millisecond to several milliseconds

Depends on graph size and traversal depth

External archive search

Network and provider dependent

Global dataset ingestion

Asynchronous distributed process

A 0.1 ms response cannot realistically guarantee a live query across every global public archive.

The solution is to pre-index datasets, cache common queries, distribute computation, and return progressively enriched results.

Quantum computation
I would make quantum computation an optional research backend, not a required dependency.

The initial implementation should use:

Parallel classical computation.

Sparse matrices.

GPU-accelerated graph operations.

Approximate nearest-neighbor indexes.

Merkle trees.

Distributed processing.

Quantum algorithms can be evaluated later against specific workloads. They do not automatically accelerate arbitrary database joins or historical identity matching.

## 2. Fractional and whole boundaries

Your delimiters have separate meanings:

| Boundary | Meaning | Execution responsibility |
|---|---|---|
| `{ }` | Fractional increments | Interleaved timing and sub-step observations |
| `( )` | Whole-cycle boundaries | Complete operator sequence and cycle closure |
| `1234` | Forward traversal | Original ordering |
| `4321` | Reverse traversal | Opposing ordering |
| `0.5` | Midpoint | Pair synchronization and comparison |

The fractional streams are complementary:

\[
F=\{0.1,0.2,\ldots,0.9\}
\]

\[
R=\{0.9,0.8,\ldots,0.1\}
\]

At each fractional checkpoint, the engine compares the corresponding paired states. At the whole-cycle boundary, it verifies that the inverse composition reconstructs the original state.

One essential mathematical safeguard: reversing the order `1234` to `4321` is only a valid inverse if each operator has a defined inverse and the inverse operations are applied in reverse composition order.

## 3. The interleaved execution rule

## 4. Each inverse adjusts against its own paired source

This is the part I would make fundamental to the kernel.

For every operator \(O_i\), the automation lane records its input, output, operator version, and sequence position. Its shadow partner independently applies the corresponding inverse.

\[
x_{i+1}=O_i(x_i;\theta_i)
\]

\[
\hat{x}_i=O_i^{-1}(x_{i+1};\hat{\theta}_i)
\]

\[
e_i=\hat{x}_i-x_i
\]

The pair evaluates its reconstruction error:

\[
\boxed{\|e_i\|\leq\tau_i}
\]

If the inverse has adjustable parameters, the shadow can calculate a bounded correction:

\[
\hat{\theta}_{i}^{(k+1)}
=
\hat{\theta}_{i}^{(k)}
-
\eta\nabla_{\theta}L_i
\]

where \(L_i\) measures reconstruction error.

There are three important rules:

1. The shadow may adjust its own inverse parameters, but never rewrite the automation lane's original input or output.
2. Every adjustment receives a new version and verification receipt.
3. If no valid inverse exists, the pair reports an unresolved state. It must not manufacture a successful reconstruction.

This gives you continuous inverse calibration rather than a single reverse operation at shutdown.

files_to_add["src/ancestry/merkle.ts"] = r'''import { createHash } from "node:crypto";

/**
 * Domain-separated SHA-256 Merkle tree.
 * Leaves: SHA256(0x00 || recordDigestBytes)
 * Nodes:  SHA256(0x01 || left || right)
 * An unpaired final node is promoted unchanged.
 */
const hash = (bytes: Uint8Array) =>
  createHash("sha256").update(bytes).digest();

export function merkleRoot(recordDigests: string[]): string {
  if (recordDigests.length === 0) return hash(new Uint8Array()).toString("hex");

  let level = recordDigests
    .slice()
    .sort()
    .map((hex) => hash(Buffer.concat([
      Buffer.from([0x00]),
      Buffer.from(hex, "hex")
    ])));

  while (level.length > 1) {
    const next: ReturnType<typeof hash>[] = [];
    for (let i = 0; i < level.length; i += 2) {
      if (i + 1 >= level.length) {
        next.push(level[i]);
      } else {
        next.push(hash(Buffer.concat([
          Buffer.from([0x01]), level[i], level[i + 1]
        ])));
      }
    }
    level = next;
  }
  return level[0].toString("hex");
}

    await rename(temp, this.sourceFile);
  }

  async addRecord(input: RecordInput): Promise<AncestryRecord> {
    if (!this.sources.has(input.sourceId)) throw new Error(`Unknown sourceId: ${input.sourceId}`);
    if (!input.title?.trim()) throw new Error("title is required");
    if (!Array.isArray(input.evidence)) throw new Error("evidence must be an array");
    if (input.recordType === "relationship") {
      if (!input.relationship?.subjectId || !input.relationship?.objectId || !input.relationship?.predicate) {
        throw new Error("relationship records require subjectId, predicate, and objectId");
      }
    }
    if (input.recordType === "person" && input.subjectStatus !== "deceased" &&
        input.accessLevel !== "restricted") {
      throw new Error("living or unknown persons must be stored as restricted records");
    }

    const now = new Date().toISOString();
    const base = {
      ...input,
      recordId: input.recordId || randomUUID(),
      createdAt: input.createdAt || now,
      updatedAt: now
    };
    const digest = sha256Hex(canonicalJson(base));
    const record: AncestryRecord = { ...base, canonicalDigest: digest };
    if (this.records.has(record.recordId)) throw new Error(`Duplicate recordId: ${record.recordId}`);

    await appendFile(this.recordFile, `${JSON.stringify(record)}\n`, "utf8");
    this.records.set(record.recordId, record);
    this.indexRecord(record);
    return record;
  }

  search(options: {
    q?: string; recordType?: string; sourceId?: string; limit?: number;
  } = {}): AncestryRecord[] {
    const limit = Math.max(1, Math.min(options.limit ?? 50, 500));
    const q = options.q ? searchKey(options.q) : "";
    let candidates: Set<string> | undefined;

    if (q) {
      candidates = new Set<string>();
      for (const [key, ids] of this.nameIndex) {
        if (key.includes(q)) for (const id of ids) candidates.add(id);
      }
    }

    return [...(candidates ?? new Set(this.records.keys()))]
      .map((id) => this.records.get(id)!)
      .filter((r) => !options.recordType || r.recordType === options.recordType)
      .filter((r) => !options.sourceId || r.sourceId === options.sourceId)
      .sort((a, b) => b.updatedAt.localeCompare(a.updatedAt))
      .slice(0, limit);
  }

  traverse(startRecordId: string, direction: "forward" | "reverse" | "both" = "both", depth = 2) {
    const maxDepth = Math.max(1, Math.min(depth, 8));
    const visited = new Set<string>([startRecordId]);
    const queue: Array<{ id: string; depth: number }> = [{ id: startRecordId, depth: 0 }];
    const edges: AncestryRecord[] = [];

    while (queue.length) {
      const current = queue.shift()!;
      if (current.depth >= maxDepth) continue;
      const incident = this.relationshipIndex.get(current.id) ?? new Set<string>();
      for (const edgeId of incident) {
        const edge = this.records.get(edgeId);
        if (!edge?.relationship || edge.evidenceStatus === "contradicted") continue;
        const { subjectId, objectId } = edge.relationship;
        const next = subjectId === current.id ? objectId : objectId === current.id ? subjectId : null;
        if (!next) continue;
        const forwardAllowed = direction === "forward" ? subjectId === current.id :
          direction === "reverse" ? objectId === current.id : true;
        if (!forwardAllowed) continue;
        edges.push(edge);
        if (!visited.has(next)) {
          visited.add(next);
          queue.push({ id: next, depth: current.depth + 1 });
        }
      }
    }
    return { startRecordId, visitedRecordIds: [...visited], edges };
  }

  stats(): DatasetStats {
    const records = [...this.records.values()];
    return {
      sourceCount: this.sources.size,
      recordCount: records.length,
      relationshipCount: records.filter((r) => r.recordType === "relationship").length,
      merkleRoot: merkleRoot(records.map((r) => r.canonicalDigest)),
      lastUpdated: records.map((r) => r.updatedAt).sort().at(-1) ?? null
    };
  }

  private rebuildIndexes(): void {
    this.nameIndex.clear();
    this.relationshipIndex.clear();
    for (const record of this.records.values()) this.indexRecord(record);
  }

  private indexRecord(record: AncestryRecord): void {
    const values = [record.title, ...(record.names ?? [])];
    for (const value of values) {
      const key = searchKey(value);
      if (!key) continue;
      if (!this.nameIndex.has(key)) this.nameIndex.set(key, new Set());
      this.nameIndex.get(key)!.add(record.recordId);
    }
    if (record.relationship) {
      for (const id of [record.relationship.subjectId, record.relationship.objectId]) {
        if (!this.relationshipIndex.has(id)) this.relationshipIndex.set(id, new Set());
        this.relationshipIndex.get(id)!.add(record.recordId);
      }
    }
  }
}
'''
